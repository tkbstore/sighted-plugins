# AEO の目的と記録

施策の良し悪しは目的で決まる。分析も制作も、目的・相手・自社の事実を押さえてから進め、前回までの前提・出来事・決定を次回に引き継ぐ。利用者と同じ言語で答える。

## 目的と要件

回す前に、記録（profile.md）と Sighted の既存データ（`list_queries` の質問、`get_query_results` の回答、GSC・GA4）で分かることを先に調べる。分かったことを示し、足りない項目だけ利用者に聞いて次を決める。分からない項目は「未定」と書き、目的が決まってから回す。

| 要件 | 決めること |
| --- | --- |
| 目的 | 増やしたい事業上の成果 |
| 相手と迷いごと | 誰が AI に何を聞き、何を比べて決めるか |
| 選ばれる理由 | 相手の判断に効く自社の事実（条件・実績・数値）。利用者から受け取る |
| 自社のチャネル | 自社サイトのドメインと、運用している SNS アカウント |
| 制約 | 法令・業界の制約、出せない情報、避けたい表現 |
| 質問の集合 | 社名の入る質問と入らない質問の一覧（ID と本文）。`list_queries` で取れる（本文は先頭 256 字で、切れると `query_truncated=true`。全文は利用者に確かめる）。目的のテーマごとの社名なしの質問 |
| 想定解 | 社名の入る質問ごとに、自社として返ってきてほしい答え。自社サイトの記載から案を作り、出典のページを添えて利用者に確かめてもらう。サイトに無い項目は空欄にして聞く。ページの本文は MCP では取れないので、Web 取得（Claude Code なら WebFetch）で読み、取れないページだけ利用者に貼ってもらう。回答の引用元 URL も同じく Web 取得で読む |
| 頻度と費用 | 再計測の間隔とクレジット。見積もりは `sighted-analysis` に従う |
| 届きうる人数の出どころ | 検索数の取得元（キーワードプランナー、GSC など）。GSC の表示回数は自社サイトの露出で、市場全体の検索数ではない |

## 記録

```
aeo/
  profile.md        前提: 上の要件・自社名の表記
  plan.md           決定: 施策ごとの仮説（狙った質問・期待した変化）、状態（提案済み／作成済み／公開済み＋公開日）、再計測の結果
  log.md            出来事: 日付・したこと・分かったこと（新しいものを上に）
  data/YYYY-MM-DD/  取得した結果と取得の範囲（期間・件数・未取得の範囲）
  reports/          出した報告
```

- 再開・提案・制作の前に、profile.md と、plan.md・log.md の直近を読む。
- 再計測したら、結果を plan.md の施策の仮説の隣に書き、仮説との差から次の施策を考える。
- 前提を変えたら、何をなぜ変えたかを log.md に書く。
- ファイルを書けない環境（claude.ai・デスクトップのチャット）では、更新した profile.md・plan.md・log.md の全文を答えの最後に出し、次回アップロードしてもらう。

次は、結果を読むなら `sighted-aeo-measure`、施策を決めるなら `sighted-aeo-content-plan`。利用者には skill 名でなく、次にできることを伝える。

# AEO の施策を決める

施策は目的から逆算する。誰のどの判断に答え、自社のどの事実で選ばれるかを決めてから、自社サイト・自社の SNS・第三者のどこで答えるかを選ぶ。利用者と同じ言語で答える。

始める前に、目的・相手・選ばれる理由・制約を確かめる（記録があれば profile.md、無ければ `sighted-aeo-context` の要件を聞く）。質問ごとの段階は `sighted-aeo-measure` の結果を使う。

## 施策の前の関門

施策を挙げる前に、需要と回答を次の順で結ぶ。GA4 は補助に使う。

GSC の検索語 → 対応する質問（`list_queries(search=)`）→ その回答に出ている企業・条件・引用元（`get_query_results`）→ 自社との差 → 施策候補

- 対応する質問や回答が無いものは「未計測」「対応未確認」と書き、推測で埋めない。先に質問を足すかを利用者に確かめる。
- 引用先の媒体だけで施策を決めない。「この媒体が引かれている」は観測、「だから載るべき」は仮説として分ける。

## 施策の種類

新規・増補・統合・内部リンク・SNS・第三者・保留から選ぶ。

- SNS: その質問で AI が SNS の投稿を引いているとき。引かれている媒体（Instagram・X・YouTube など）で、質問への答えになる投稿を自社アカウントから出す。
- 第三者: 「記載はあるが挙がらない」段階で、他社が第三者の掲載から紹介されているとき（`sighted-aeo-measure` の質問ごとの段階）。自社が主語になる露出（取材・寄稿・発表・導入事例）を候補にする。
- 保留: 需要・目的との適合・重複・素材のどれかが判断できないとき。解除の条件を書く。

- 既存ページとの重複は、利用者から受け取ったページ一覧と、Web 取得で読んだ本文で確かめる（MCP では任意 URL の本文を取れない）。
- 引用元のページは Web 取得で必要な範囲を読む（計測時と今の内容は同じとは限らない）。
- AI の引用はドメインごとに積まれる。比較サイトに載った分はそのサイトに積まれるので、露出先を選ぶ前に運営主体を確かめる。
- 優先度は需要の証拠で上げる。他社も自社も引用されていない質問は、需要の大小を引用の有無から推測せず、「引用なし」と観測だけを書く。需要の証拠は、検索数・問い合わせ記録など出どころと期間が分かるものを使う。

## 一次情報ブリーフ

記事や投稿に使う事実は、公開済みの情報と当事者への確認で集める。料金・実績・事例の数値は、AI の回答ではなく現在の公式ページか当事者から取る。

| 項目 | 中身 |
| --- | --- |
| 目的と相手 | 誰のどの判断に答えるか、何につなげるか |
| 媒体と形式 | 自社サイトの記事、Instagram の投稿など |
| 答える論点 | 質問で使われる語と、それへの答え |
| 確認済みの事実 | 出典・確認日 |
| 要確認の事実 | 当事者への質問・担当・期限。未確定のまま残す |
| 制約 | 出せない情報、避けたい表現 |

## 計画の書き方

候補ごとに次の 5 段で書き、埋まらない段は入手先を添えて保留にする。

| 段 | 中身 |
| --- | --- |
| 対象の質問 | 質問と、社名あり／なし |
| 今の引用元 | その質問で引かれている URL・運営主体と確認日。回答の根拠（質問ID・結果ID・計測日時） |
| 施策 | 種類と対象（URL・アカウント） |
| 足す情報 | 記事や投稿に置く答えと事実、その確定状態 |
| 次回の確かめ方 | 期待する変化、再計測する質問・時点、反証になる結果と、続ける・直す・やめる条件 |

- 施策の状態は「提案済み」「作成済み」「公開済み＋公開日」で記録する。公開済みは、サイトのページなら一覧ページや内部リンクから辿れ、インデックスされたことまで、SNS の投稿なら投稿の URL を確かめて付ける。
- SNS の投稿の反応は、Facebook・Instagram なら `fb_post_insights`・`ig_media_insights` で見る。他の媒体の数字は利用者から受け取る。広告のデータの扱いは `sighted-analysis` に従う。

報告の前は `sighted-deliverable-check` へ。利用者には skill 名でなく、次にできることを伝える。

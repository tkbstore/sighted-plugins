# AEO の結果を読む

見るのは、他社が AI に挙げられ、自社が挙げられない場面である。それが **どの質問で、どれくらいの頻度で起き、何人の判断に届きうるか** を数え、原因を切り分けて施策に渡す。利用者と同じ言語で答える。

Sighted のツールの使い方・費用・実行・エラーは `sighted-analysis` に従う。目的と前提は、記録があれば profile.md から読む（`sighted-aeo-start`）。

## 出すもの

| 項目 | 中身 |
| --- | --- |
| 空白の場面 | 社名なしの質問で、自社と他社がそれぞれ挙がった回答の数。どの他社が、どの側面（料金・条件・実績など）で紹介されたか |
| 質問と頻度 | 質問ごとの「挙がった回数 / 回答数」 |
| 届きうる人数 | 対応する検索語の月間検索数と、その出どころ・取得日。取れなければ空欄 |
| 原因 | 下の 4 分類と、その根拠 |
| 社名ありの質問 | 古い情報・誤った情報・別会社の情報の混入を、回答の原文と回数で示す |
| 再調査で見る指標 | 施策ごとの指標と現状値 |

## 読み方

- 社名の入る質問と入らない質問を分けて数える。質問の本文は MCP で取れないので、profile.md か利用者から受け取った質問の一覧（ID と本文）で分ける。社名の入る質問は回答が社名を繰り返すだけで言及になるので、伸びしろは社名なしの質問で見る。利用者が「一般の質問で出てこない」と心配しているときは、まずこれを伝える。
- 言及（名前が出た）と引用（自社の URL が出典になった）を分けて数える。`get_query_trends` の言及数は登録キーワードの出現回数、引用数は他社も含む出典 URL の総数なので、自社と他社を分けるときは `raw` から数える。
- 他社は `get_query_results` の回答（`raw`）から拾い、紹介に添えられた条件も抜き出す。業界一般の説明が特定の会社に紐づく側面は、原文で確かめてから出す。
- 判定の前に、回答に出る自社名の書き方（記号・全角半角・カナ）を原文から集める。
- 出典の種類は、名前で分かるドメインだけ分類し、残りは「不明」とする。SNS の URL はアカウントを見て、自社の投稿か他者の投稿かを分ける。Sighted は自社サイトのドメイン以外を他社の引用として数えるので、自社アカウントの投稿の引用は自社の引用数に入らない。
- 取れなかった範囲（上限での打ち切り・計測開始前・別サイトの接続）は「未取得」と書く。`get_query_results` は `limit` 件で新しい順に切れるので、返った件数が `limit` に届いたら期間を短くして取り直す。
- 検索数は Sighted の外の数字なので、利用者に用意してもらうか、GSC の表示回数（自社サイトに関する語で、`gsc_top_queries` はクリックの多い上位 100 語まで）で代える。
- 期間を比べるときは、質問の集合とエンジンが同じかを確かめ、違えばそれを書く。

## 原因の 4 分類

| 分類 | 見え方 | 施策の向き |
| --- | --- | --- |
| 記載はあるが選ばれていない | 自社にも同じ側面の記載があり、他社は自社ページから紹介される | 質問で使われる語を見出し・本文に明記、記事で補う |
| 外部の掲載先で負けている | 他社は比較サイト・ポータル・SNS の投稿など、自社サイトの外から紹介される | 第三者の掲載の整備、SNS での発信 |
| 条件で負けている | 紹介の決め手が数値の条件で、自社の条件が劣る | 対象から外すか、利用者の判断に委ねる |
| 守備範囲外 | 公的機関や別業態が占める | 対象から外す |

決められないものは「未確定」とし、確かめる方法を書く。

## 効果を言う前に

- 施策のテーマに合う社名なしの質問の数を数える。0 問なら、先に質問を足す（作成は Sighted の画面）。
- 効果に数えるのは、施策の後に「公開済み」になったページだけにする（確かめ方は `sighted-aeo-content-plan`）。
- 変化した場所と施策の効果は別の主張として書き、反する例が無いかを確かめる。

施策の計画は `sighted-aeo-content-plan`、報告の前は `sighted-deliverable-check` へ。利用者には skill 名でなく、次にできることを伝える。

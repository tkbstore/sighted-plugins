# AEO の施策を決める

施策は目的から逆算する。誰のどの判断に答え、自社のどの事実で選ばれるかを決めてから、作る・直す・載ってもらう先を選ぶ。利用者と同じ言語で答える。

始める前に、目的・相手・選ばれる理由・制約を確かめる（記録があれば profile.md、無ければ `sighted-aeo-start` の要件を聞く）。空白の場面と原因は `sighted-aeo-measure` の結果を使う。

## 施策の種類

新規・増補・統合・内部リンク・第三者・保留から選ぶ。

- 第三者: 原因が「外部の掲載先で負けている」とき（`sighted-aeo-measure` の原因の 4 分類）。自社が主語になる露出（取材・寄稿・発表・導入事例）を候補にする。
- 保留: 需要・目的との適合・重複・素材のどれかが判断できないとき。解除の条件を書く。

- 既存ページとの重複は、利用者から受け取ったページ一覧と本文で確かめる（MCP では任意 URL の本文を取れない）。
- AI の引用はドメインごとに積まれる。比較サイトに載った分はそのサイトに積まれるので、露出先を選ぶ前に運営主体を確かめる。
- 優先度は需要の証拠で上げる。他社も自社も引用されていない質問は、需要が小さい可能性と並べて書く。需要の証拠は、検索数・問い合わせ記録など出どころと期間が分かるものを使う。

## 一次情報ブリーフ

記事に使う事実は、公開済みの情報と当事者への確認で集める。料金・実績・事例の数値は、AI の回答ではなく現在の公式ページか当事者から取る。

| 項目 | 中身 |
| --- | --- |
| 目的と相手 | 誰のどの判断に答えるか、何につなげるか |
| 本文で答える論点 | 質問で使われる語と、それへの答え |
| 確認済みの事実 | 出典・確認日 |
| 要確認の事実 | 当事者への質問・担当・期限。未確定のまま残す |
| 制約 | 出せない情報、避けたい表現 |

## 計画の書き方

候補ごとに次の 5 段で書き、埋まらない段は入手先を添えて保留にする。

| 段 | 中身 |
| --- | --- |
| 対象の質問 | 質問と、社名あり／なし |
| 今の引用元 | その質問で引かれている URL・運営主体と確認日 |
| 施策 | 種類と対象 URL |
| 足す情報 | 本文に置く答えと事実、その確定状態 |
| 次回の確かめ方 | 再計測する質問・時点と、続ける・直す・やめる条件 |

- 施策の状態は「提案済み」「作成済み」「公開済み＋公開日」で記録する。公開済みは、一覧ページや内部リンクから辿れ、インデックスされたことまで確かめて付ける。

報告の前は `sighted-deliverable-check` へ。利用者には skill 名でなく、次にできることを伝える。
